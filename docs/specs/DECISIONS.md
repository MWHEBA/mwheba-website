4. Explicit project owner approval.

### D-018 problem statement, alternatives, and impact

- **Problem.** Inventory-free checkout cannot protect the last sellable units under concurrent orders or support audited restoration after eligible cancellations and inspected returns.
- **Alternatives reviewed.** Keeping inventory out of scope cannot meet the last-units guarantee. The installed Payload Ecommerce plugin has native inventory enabled by default in its product and variant collection factories. Its `confirmOrder` path decrements inventory after order creation with `$inc`, but it has no stock-movement ledger or the required custom cancellation and return restoration boundary. The selected approach keeps native inventory disabled and implements one dedicated SKU balance and movement service in the existing PostgreSQL order and transition transactions.
- **Pinned-package evidence.** Installed `@payloadcms/plugin-ecommerce` is 3.91.0. Its `dist/collections/products/createProductsCollection.js` and `dist/collections/variants/createVariantsCollection/index.js` add inventory fields by default. Its `dist/endpoints/confirmOrder.js` calls `decrementInventory` after order creation and applies `inventory: { $inc: item.quantity * -1 }`. That path writes no movement record. This review confirms the installed behavior and does not evaluate every possible plugin customization.
- **Impact.** Implementation requires additive stock and movement schema, deterministic SKU locking or conditional decrement, transactionally coupled order, cart, and fulfillment writes, role-gated adjustment and restoration workflows, migration coverage, and concurrent transaction tests. Unknown opening balances remain unavailable. This decision authorizes implementation only. It does not authorize merchant data, opening balances, imports, legacy-order allocations, production cutover, or a notification channel.
- **Approval source.** Owner's direct instruction in this task was `نفّذ inventory.md وorders.md`, with explicit authorization for atomic decrement and restoration. It supersedes D-018's prior inventory exclusion only within this implementation scope.
